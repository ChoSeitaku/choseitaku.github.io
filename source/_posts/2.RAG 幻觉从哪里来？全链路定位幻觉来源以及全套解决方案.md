# RAG 幻觉从哪里来？全链路定位幻觉来源以及全套解决方案

> 📌 本文基于线上落地**StarRag企业知识库项目**实战总结，对应真实面试高频考点。很多同学做完 RAG Demo 发现：明明接入了知识库，大模型依然一本正经胡说八道。幻觉不是简单改一句 Prompt 就能根治，它分布在文档预处理、切片、检索、重排、生成的整条链路。本文结合项目踩坑，拆解幻觉来源、全链路排查定位流程、分层工程解决方案，同时给出 BadCase 分析思路。
> 
> 🔖适合人群：做企业 RAG 落地、准备大模型应用面试、想要区分 Demo 和生产级 RAG 差异的开发者。

## 前言

很多人对 RAG 有一个误区：只要把文档放进向量库，大模型就不会产生幻觉。但在我们**StarRag（电商产品知识库）**项目上线之后，依然遇到大量幻觉案例：

1. 把 A 商品的参数安到 B 商品身上（实体混淆）；
2. 知识库写的保修 1 年，大模型输出保修 3 年；
3. 检索返回的片段本身没有答案，模型强行编造答案；
4. 多份新旧版本手册同时存在，模型引用过期文档；
5. 模型只读取切片头部，忽略中间关键证据，得出错误结论。

幻觉不是单一环节问题，**会发生在文档预处理→切片→向量化→多路召回→Rerank 重排→Prompt 组装→LLM 生成整条链路**。不能只靠提示词一句 “请基于上下文回答” 解决。本文结合项目实战，拆解幻觉来源、标准化排查流程、分层全套工程解决方案。

项目技术栈：`FastAPI + LangGraph + Milvus + MinerU + BGE‑M3 + BGE‑Reranker‑large + MinIO + MongoDB`

## 一、RAG 幻觉两大分类

### 1）检索源头类幻觉（占大多数）

> 根源：送入大模型的上下文本身就错、缺失、混杂噪声。

- 完全没有召回正确证据，模型使用预训练固有知识编造；
- 召回一堆半相关噪声片段，误导模型；
- 召回了过期、冲突文档，新旧版本混在一起；
- 商品实体识别错误，把别的产品切片混入上下文。

### 2）生成层幻觉（检索结果没问题，但模型输出出错）

> 根源：证据已经给到，但大模型 “超发挥”。

- 无视参考资料，自己脑补细节；
- 拼接多个无关切片，错误融合信息；
- 只看上下文首尾，忽略中间关键切片；
- 拒绝输出 “不知道”，强制要给出确定答案。

> 项目实战经验：**70% 以上幻觉根源出现在检索链路，不是大模型生成环节。治幻觉先治检索，只优化 Prompt 治标不治本。**

## 二、全链路拆解：每一个环节如何诱发幻觉

### 阶段 1：文档预处理环节（写入链路）

1. PDF 解析失败，表格、图片关键信息丢失；图片没有生成 VLM 摘要，关键故障信息完全缺失；
2. 知识库同时存在新旧版本手册，没有版本标记，新旧内容冲突；
3. 文档内存在矛盾描述，没有做冲突检测；

> 现象：正确事实从源头就消失，后续再优秀检索也拿不到正确证据，模型只能编造。

### 阶段 2：Chunk 切片环节

1. Chunk 切分粗暴，把一条完整事实切到两个不同切片，单独任意一个 chunk 都不能完整表达事实；
2. Chunk 过大，大量无关信息被塞进同一个切片，噪声稀释有效信息；
3. 缺少元数据：没有`item_name`、文档版本、来源标题，检索时无法过滤错误商品、过期文档；

> 现象：召回片段只有半条事实，模型脑补补齐缺失部分，产生错误答案。

### 阶段 3：向量化 & 多路召回环节

1. Embedding 模型效果差，语义匹配失效，正确的文档没有召回；
2. 仅使用稠密向量，专有名词、型号召回失败；
3. HyDE 假设文档生成跑偏，虚假假设文档被召回，引入虚假证据；
4. 实体识别失败，没有做标量过滤，混入其他商品的切片；

> 现象：返回一堆语义看着近似，但实际完全无关的候选切片。

### 阶段 4：RRF 融合 & Rerank 重排环节

1. 没有做重排，直接拿向量检索结果送入 LLM；
2. 不做分数过滤，低分噪声片段直接放行进入 Prompt；
3. 写死固定 TopK，塞入大量低相关性候选；
4. 高分有效切片排在列表靠后，大模型只读取首尾，忽略中间证据。

### 阶段 5：Prompt 组装 & LLM 生成环节

1. Prompt 约束不足，没有 “无答案请拒答” 的强制指令；
2. temperature 设置过高，增加模型随机编造概率；
3. 上下文过载，大量噪声片段塞满窗口；
4. 模型天然倾向输出确定答案，不愿意输出 “我不知道”。

### 阶段 6：上线后缺少评测闭环

没有 BadCase 收集、没有 RAGAS 评测，幻觉问题持续积累无法迭代优化。

## 三、生产环境：幻觉 BadCase 标准化排查流程（StarRag项目线上流程）

> 面试高频：线上遇到幻觉 case，你排查的步骤是什么？ 拿到一条幻觉样本，严格顺着整条链路向下排查：

1. **确认原始知识库**：知识库原始文档中，是否真实存在该问题对应的标准答案？
    - 不存在：属于知识库缺失，补充文档；
    - 存在：继续往下排查链路。
2. 查看**文档解析结果**：PDF / 表格 / 图片信息是否完整解析，关键内容有没有丢失。
3. 查看**切片结果**：这条事实是否被完整保存在某一个 chunk，是否被切分到多个分片。
4. 查看**召回全链路日志**：
    - 多路召回（普通向量、HyDE），正确的 chunk 有没有出现在召回候选集合？
    - 商品实体识别是否正确，有没有混入其他商品的切片？
5. 查看**RRF 融合、Rerank 打分**：
    - 正确切片重排之后分数多少？是否被断崖截断过滤掉？
    - 最终送入 LLM 的上下文集合里面，是否包含正确 chunk？
6. 如果正确切片已经送入 Prompt：问题属于**生成层幻觉**，优化提示词、temperature、增加引用约束。
7. 如果正确切片没有送入 Prompt：属于**检索链路幻觉**，优化解析、切片、embedding、召回、重排参数。
8. 记录 BadCase，进入测试集，迭代之后回归复测。

> 关键：区分幻觉根源，不要拿到幻觉就直接改 Prompt。很多问题根源在前面预处理、检索环节。

## 四、全套分层工程解决方案（从源头到生成，StarRag落地实践）

### 🟢第一层：源头治理 —— 文档预处理、知识库治理（写入链路，优先级最高）

1. PDF 使用 MinerU 解析，表格线性化，图片调用 VLM 生成摘要，避免关键信息解析丢失；
2. 文档增加版本元数据，导入时标记版本，旧文档可以做废弃标记，检索过滤过期文档；
3. 文档导入阶段做简单冲突检测，同一文档内矛盾内容人工介入处理；
4. 上线前清洗脏文档、残缺扫描件。

### 🟢第二层：切片 Chunk 优化，减少事实割裂

1. 优先按 Markdown 标题层级切分，避免暴力按字符切割把一条事实拆成多块；
2. 合理设置参数：最大 1200 字符，最小 300 字符，句子重叠`overlap_sentences=1`；
3. **每个 Chunk 必须挂载完整元数据**：`file_title`、`parent_title`、`item_name`、文档版本；查询阶段利用`item_name`做 Milvus 标量过滤，过滤其他商品切片；
4. 长语义片段：开启句子重叠；进阶保存`parent_chunk_id`，命中子切片回填父章节。

### 🟢第三层：检索链路优化，从源头给到模型高质量证据

1. 使用 BGE‑M3 稠密 + 稀疏混合检索，兼顾语义改写和专有名词型号匹配；
2. HyDE 只作为一路召回来源，**不能作为唯一证据来源**，后续交给 Rerank 过滤 HyDE 跑偏带来的噪声；
3. 多轮对话通过 LLM 做商品实体抽取，实体识别成功做标量过滤，防止跨商品实体混淆；
4. 多路召回之后使用 RRF 做廉价粗融合，压缩候选集。

### 🟢第四层：重排 + 动态截断，拦截低分噪声片段

1. 必须接入 Rerank 交叉编码做精排，不能直接使用向量相似度分数；
2. **放弃固定 TopK，使用断崖检测动态截断**；最少保留 6，最多 15；相邻切片分数绝对差 0.5 / 相对差 25% 触发截断；设置最低相关性阈值，全部低于阈值直接拒答，不送入大模型；
3. 缓解模型忽略中间切片：Rerank 保证高相关性切片尽量靠前；Prompt 强制逐条阅读全部参考资料。

### 🟢第五层：生成层防护，多道防线约束大模型输出

1. Prompt 强制约束（项目实际提示词片段）

```
你只能严格依据下面提供的参考资料回答用户问题。
如果参考资料中没有对应信息，请如实回复：【知识库未查询到相关信息】，禁止编造任何事实，禁止使用你本身的内部知识作答。
回答时请标注对应的资料来源文档名称。
```

2. 事实类问答调低`temperature`，降低随机生成带来脑补；
3. 强制输出引用来源，每条结论绑定切片来源，便于排查；
4. 高危业务场景：增加后校验，再次调用 LLM 校验答案是否可以被检索片段支撑。

### 🟢第六层：评测与 BadCase 闭环（上线之后必不可少）

1. 离线评测 RAGAS 重点观测两个指标：

- `faithfulness`：答案是否忠实上下文，直接衡量幻觉；
- `context_recall`：召回是否拿到全部事实证据。

2. 两条 BadCase 收集路径：
    - 用户端：前端 “答案无帮助” 反馈按钮；
    - 日志采样：线上采样，`faithfulness`低分样本自动归入 BadCase 库。
3. 每一轮迭代之后，使用 BadCase 测试集做回归测试，避免改完 A 问题又引入 B 问题。

## 五、项目踩坑复盘（StarRag真实线上幻觉案例）

1. ❌坑：图片故障示意图没有做 VLM 摘要，图片里故障现象完全检索不到，模型编造故障处理步骤。 ✅解决：MinerU 提取图片引用，VLM 生成图片摘要参与检索。
2. ❌坑：没有元数据过滤，查询 A 商品，混入 B 商品切片，参数张冠李戴。 ✅解决：Chunk 挂载`item_name`，查询阶段 Milvus 标量过滤。
3. ❌坑：HyDE 生成虚假的假设文档，虚假文档被召回，模型基于虚假文档输出答案。 ✅解决：HyDE 仅一路召回，交给 Rerank 打分过滤低分虚假片段。
4. ❌坑：写死 Top‑10，大量低分噪声送入 Prompt，模型被噪声误导。 ✅解决：断崖动态截断 + 最低相关性阈值，全部分数过低直接拒答。
5. ❌坑：只靠一句 Prompt 约束，检索结果已经全是无关内容，模型依然强行编造。 ✅解决：**检索层设置防线，不要把全部希望寄托在大模型自律**，噪声在送入 LLM 之前拦截。

## 六、关键认知总结

1. RAG 幻觉≠大模型单方面问题，**70% 根源出现在预处理、切片、检索链路，不是生成 Prompt**。检索源头垃圾，再好的提示词也无法避免胡说。
2. 不存在完全消除幻觉的银弹，我们做多层防线降低幻觉发生概率。
3. 宁可拒答说 “知识库没有找到信息”，不要让模型输出自信的错误答案。
4. 完整的 RAG 抗幻觉体系：**文档治理 → 切片元数据 → 高质量多路检索 → Rerank + 动态截断过滤噪声 → 生成层约束 → BadCase 评测闭环**。

## ✨博客附加：配套面试真题（全部来源于两份原始文档，可直接粘贴到博客末尾）

> 配套面试真题 + 真实项目回答，面试高频，全部结合StarRag项目实战。

### Q1：你们项目 RAG 幻觉一般是什么原因，怎么定位排查？

**回答：** RAG 幻觉分两大类，检索源头幻觉、生成层幻觉，我们StarRag项目 70% 左右幻觉根源来自检索链路。 完整排查步骤：

1. 第一步确认原始知识库文档，看标准答案是否真实存在；
2. 检查文档解析：PDF、表格、图片关键信息有没有丢失；
3. 查看切片，完整事实是否被完整保存，是否被切割到多个 chunk；
4. 查看召回链路日志：多路召回结果、商品实体识别结果，正确 chunk 有没有进入候选；
5. 看 RRF、Rerank 打分，正确切片是否被截断过滤；
6. 看最终送入 LLM 的 prompt 上下文：
    - 如果正确证据**没有进入上下文**：属于检索链路幻觉，优化解析、切片、embedding、召回重排参数；
    - 如果正确证据**已经送入上下文**：属于生成层幻觉，优化提示词、temperature、增加引用校验。
7. 将 case 存入 badcase 库，迭代之后回归复测。

### Q2：HyDE 会不会带来幻觉？项目怎么处理 HyDE 跑偏？

**回答：** HyDE 会带来幻觉。当用户问题领域冷门，大模型生成完全虚构的假设文档，虚构文档进入召回候选，就引入虚假证据。 我们项目不会把 HyDE 作为唯一召回来源，它只是三路召回的其中一路；生成的假想文档对应的候选，会和普通向量检索结果一起进入 RRF 融合，再交给 Rerank 重排，低分的跑偏的候选会被过滤掉，避免虚假证据送入大模型。

### Q3：已经做了 RAG，依然出现 A 商品参数跑到 B 商品，实体混淆幻觉，你们怎么解决？

**回答：** 根源：多轮对话代词指代识别失效，检索的时候没有过滤其他商品的切片。 我们项目每一个 chunk 都挂载`item_name`商品名元数据；多轮对话读取 MongoDB 历史会话，LLM 做商品实体抽取；识别成功后，Milvus 检索使用`item_name`做标量过滤，直接过滤其他商品的切片，从检索源头杜绝不同商品的切片混入上下文。置信度不足的时候反问用户确认商品。

### Q4：检索出来的切片，大模型只看头部尾部，中间有效片段被忽略，会带来幻觉，项目怎么处理？

**回答：**

1. 使用 Rerank 重排，保证高相关性切片尽量排在列表靠前；
2. 放弃固定 TopK，断崖检测动态截断；设置最低分数阈值，低分直接拦截；
3. Prompt 显式约束大模型逐条阅读全部参考资料，禁止只阅读首尾；
4. 必要场景做切片回填，把子块对应的父章节补充进上下文。

### Q5：是不是 Prompt 写严格一点就可以解决 RAG 幻觉？

**回答：** 不可以，Prompt 只是最后一道防线，不能解决上游链路问题。 如果送入大模型的上下文本身就是噪声、错误、过期文档，无论提示词写得多严格，大模型依然会输出错误内容。 生产项目必须优先治理文档、切片、检索、重排，拦截噪声在送入 LLM 之前；Prompt 约束只是最后一层防护，不能作为唯一解决方案。

### Q6：RAGAS 里面哪个指标重点看幻觉？其他指标分别代表什么？

**回答：** `faithfulness`忠实度指标直接衡量幻觉，代表生成答案是否严格忠实于检索上下文。

- `faithfulness`：答案忠实于上下文，越低幻觉越严重；
- `context_recall`：召回切片是否包含参考答案全部事实；
- `context_precision`：召回结果噪声多少；
- `answer_relevancy`：回答是否贴合用户原始问题。 线上 BadCase 采样，重点监控`faithfulness`低分样本。

### Q7：知识库文档内部存在冲突、新旧版本同时存在，怎么减少幻觉？

**回答：**

1. 文档导入阶段，给 chunk 增加版本元数据；旧文档标记废弃状态；检索阶段过滤已经废弃的文档；
2. 导入阶段人工做冲突检测；
3. Rerank 阶段新版本文档可以调高权重，优先把新版内容排到前面；
4. BadCase 中如果出现新旧文档冲突的 case，推动业务更新清理知识库。

### Q8：Chunk 切片不合理为什么会带来幻觉？有哪些典型切片坑？

**回答：** 切片策略会直接影响证据完整性，不合理切片会诱发幻觉。

1. Chunk 切分粗暴，把一条完整事实拆分到两个不同 chunk，任何单个分片都拿不到完整事实，模型只能脑补补齐缺失部分；
2. Chunk 设置过大，大量无关信息混入同一个切片，有效信息被噪声稀释；
3. 缺少元数据，无法做实体、版本过滤，混入无关文档片段。

我们项目的切片策略：优先 Markdown 标题层级切分，大章节再递归字符切分；参数最大 1200 字符，最小 300 字符，`overlap_sentences=1`；每个 chunk 挂载完整元数据`file_title、parent_title、item_name`。

### Q9：RAG 上线响应正常，但是幻觉变多，你的排查思路？

**回答：** 幻觉变多，我们按链路逐层看日志：

1. 先确认知识库有没有变更：是否新导入大量脏文档、过期文档；
2. 看导入链路：解析逻辑、切片参数、embedding 模型是否有版本变更；
3. 查询链路：实体抽取效果、多路召回候选集合，正确证据是否还能被召回；
4. 检查 RRF、Rerank：阈值、断崖截断参数是否改动，高分有效切片是否被过滤；
5. 查看 Prompt、temperature 参数是否被修改；
6. 提取线上 badcase，用 RAGAS 看`faithfulness、context_recall`指标变化，定位哪一层退化。

### Q10：为什么只用稠密 dense 向量检索更容易产生幻觉？

**回答：** 稠密向量擅长语义同义改写，但是对专有名词、设备型号、零件编号匹配能力弱。 只使用 dense 向量，经常出现：用户问具体型号，召回一堆语义近似但是型号完全不匹配的文档，带来大量噪声，进而诱发幻觉。 BGE‑M3 同时输出 dense 稠密向量和 sparse 稀疏向量（等效 BM25），稀疏向量擅长关键词、型号精确匹配。两路混合检索，减少无关候选，降低幻觉风险。
