# 尚品汇电商系统 - 微服务架构实践

> 一个基于 Spring Cloud Alibaba 的分布式微服务电商平台，支持 PC 后台管理 + H5 移动端双端访问。

## 项目简介

尚品汇是一套完整的 B2C 电商系统，采用前后端分离架构，基于若依框架二次开发。项目涵盖商品管理、购物车、订单、支付、用户管理等电商核心业务，实现了从商品浏览到下单支付的完整购物流程。

**技术栈**：Spring Boot 3.0 + Spring Cloud Alibaba + MyBatis-Plus + Redis + RabbitMQ + MinIO  
**项目规模**：10+ 微服务模块，50+ 数据库表  
**项目地址**：https://github.com/ChoSeitaku/shangpinhui-ecommerce

### 2. 商品模块 (spzx-product) - 核心模块

**功能概述**：商品的全生命周期管理，包括商品发布、上下架、库存管理等。

**核心表结构**：
```sql

-- 商品SKU表

-- 库存表

-- 商品详情表

-- 分类表

-- 品牌表
```

**技术亮点**：

#### 1. Redis位图实现商品上下架快速判断
```java
// 上架商品：将SKU ID写入位图
redisService.setBit("product:bitmap", skuId, true);

// 下架商品：从位图移除
redisService.setBit("product:bitmap", skuId, false);

// 判断商品是否上架：O(1)时间复杂度
Boolean isExist = redisService.getBit("product:bitmap", skuId);
```

**设计思路**：使用 Redis Bitmap 存储商品上下架状态，相比传统方案（查询数据库或普通缓存），具有以下优势：
- 内存效率极高：每个商品只占用1个bit位
- 查询时间复杂度 O(1)：直接位运算
- 支持批量操作：可一次性查询多个商品状态

#### 2. 分布式锁 + Lua脚本的缓存查询
```java
public ProductSku getProductSkuById(Long skuId) {
    // 1. 先查缓存
    ProductSku productSku = redisService.getCacheObject("product:sku:" + skuId);
    if (productSku != null) {
        return productSku;
    }
    
    // 2. 获取分布式锁
    String lockKey = "lock:product:sku:" + skuId;
    boolean isLock = redisService.setIfAbsent(lockKey, "1", 5, TimeUnit.SECONDS);
    
    if (isLock) {
        try {
            // 3. 获锁成功，查询数据库
            productSku = productSkuMapper.selectById(skuId);
            // 4. 写入缓存（空值也缓存，防止穿透）
            if (productSku != null) {
                redisService.setCacheObject("product:sku:" + skuId, productSku, 5, TimeUnit.MINUTES);
            } else {
                redisService.setCacheObject("product:sku:" + skuId, null, 1, TimeUnit.MINUTES);
            }
        } finally {
            // 5. Lua脚本原子释放锁
            String script = "if redis.call('get', KEYS[1]) == ARGV[1] then return redis.call('del', KEYS[1]) else return 0 end";
            redisService.execute(script, Collections.singletonList(lockKey), "1");
        }
    } else {
        // 6. 获锁失败，自旋重试
        Thread.sleep(100);
        return getProductSkuById(skuId); // 递归调用
    }
    return productSku;
}
```

**设计思路**：
- **防缓存击穿**：分布式锁确保只有一个线程查询数据库
- **防缓存穿透**：空值也缓存，设置较短过期时间
- **原子释放锁**：Lua脚本保证比较+删除的原子性
- **自旋重试**：获锁失败时等待后重试，提高成功率

#### 3. 数据库乐观锁实现库存扣减
```sql
-- 锁定库存（CAS方式）
UPDATE sku_stock 
SET available_num = available_num - #{skuNum},
    total_num = total_num - #{skuNum},
    sale_num = sale_num + #{skuNum}
WHERE id = #{skuId} AND available_num >= #{skuNum}
```

**设计思路**：
- 通过 `WHERE available_num >= #{skuNum}` 条件保证不会超卖
- 数据库层面的原子操作，无需引入Redis预扣减
- 返回影响行数为0时，表示库存不足

### 3. 购物车模块 (spzx-cart)

**功能概述**：用户购物车的增删改查，完全基于 Redis 存储，不落库。

**存储设计**：
```
Redis Key: user:cart:{userId}
Redis Field: skuId
Redis Value: CartInfo对象（JSON序列化）
```

**核心功能**：

| 功能 | 实现方式 |
|------|----------|
| 添加购物车 | HGET判断是否存在，HSET写入 |
| 查看购物车 | HGETALL获取所有商品，远程调用获取实时价格 |
| 修改数量 | HSET更新数量字段 |
| 选中/取消选中 | HSET更新checkStatus字段 |
| 删除商品 | HDEL删除指定field |
| 清空购物车 | DEL删除整个key |

**为什么选择Redis Hash**：
- 购物车数据不需要持久化，Redis完全满足
- Hash结构天然支持按用户隔离
- 读写性能远高于数据库
- 支持单个商品的独立操作

### 6. 渠道模块 (spzx-channel) - BFF聚合层

**功能概述**：H5前台的 BFF（Backend For Frontend）聚合层，不直接操作数据库，而是远程调用各微服务聚合数据。

**商品详情页聚合示例**：
```java
public ItemVo item(Long skuId) {
    ItemVo itemVo = new ItemVo();
    
    // 1. Redis位图快速判断商品是否存在
    Boolean isExist = redisService.getBit("product:bitmap", skuId);
    if (!isExist) {
        throw new ServiceException("商品已下架");
    }
    
    // 2. 远程调用：获取SKU信息
    ProductSku productSku = remoteProductService.getSkuInfo(skuId);
    
    // 3. 远程调用：获取商品信息 + 轮播图 + 规格列表
    Product product = remoteProductService.getProductInfo(productSku.getProductId());
    
    // 4. 远程调用：获取最新价格
    BigDecimal price = remoteProductService.getPrice(skuId);
    
    // 5. 远程调用：获取商品详情图片
    ProductDetails details = remoteProductService.getDetails(productSku.getProductId());
    
    // 6. 远程调用：获取规格-SKU映射关系
    Map<String, Long> specSkuMap = remoteProductService.getSpecSkuMap(productSku.getProductId());
    
    // 7. 远程调用：获取库存信息
    SkuStock stock = remoteProductService.getStock(skuId);
    
    // 封装返回
    itemVo.setProductSku(productSku);
    itemVo.setProduct(product);
    itemVo.setDetails(details);
    itemVo.setSpecSkuMap(specSkuMap);
    itemVo.setStock(stock);
    
    return itemVo;
}
```

**设计思路**：
- 前端只需调用 channel 层的接口，无需关心后端微服务划分
- 一次请求聚合多个远程调用，减少前端请求次数
- 前后端解耦，后端服务拆分不影响前端

## 技术亮点

### 1. 延迟消息实现订单超时自动取消

**问题**：用户下单后30分钟内未支付，需要自动取消订单并解锁库存。

**解决方案**：使用 RabbitMQ 延迟消息插件。

```java
// 提交订单成功后，发送延迟消息
rabbitService.sendDelayMessage(
    MqConst.EXCHANGE_CANCEL_ORDER,    // 交换机
    MqConst.ROUTING_CANCEL_ORDER,     // 路由键
    orderNo,                          // 消息内容
    30 * 60 * 1000                    // 延迟30分钟
);

// 消息接收者
@Component
@RabbitListener(queues = MqConst.QUEUE_CANCEL_ORDER)
public class OrderReceiver {
    
    @RabbitHandler
    public void cancelOrder(String orderNo) {
        // 1. 查询订单状态
        OrderInfo orderInfo = orderInfoMapper.selectByOrderNo(orderNo);
        
        // 2. 如果仍为"待支付"，执行取消
        if (orderInfo != null && orderInfo.getOrderStatus() == 0) {
            // 更新订单状态为已取消
            orderInfo.setOrderStatus(-1);
            orderInfoMapper.updateById(orderInfo);
            
            // 远程调用解锁库存
            remoteProductService.unlockStock(orderNo);
            
            // 记录订单日志
            orderLogMapper.insert(...);
        }
    }
}
```

### 2. Feign调用安全传递用户信息

**问题**：微服务间 Feign 调用时，如何传递当前登录用户信息？

**解决方案**：网关解析JWT后写入请求头，Feign拦截器自动携带。

```java
// 1. 网关解析JWT，写入请求头
@Component
public class AuthFilter implements GlobalFilter, Ordered {
    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        // 解析JWT获取用户信息
        String userId = parseJwt(token);
        String username = parseJwt(token);
        
        // 写入请求头，传递给下游服务
        ServerHttpRequest request = exchange.getRequest().mutate()
            .header("user-id", userId)
            .header("username", username)
            .build();
        
        return chain.filter(exchange.mutate().request(request).build());
    }
}

// 2. Feign拦截器自动携带请求头
@Component
public class FeignRequestInterceptor implements RequestInterceptor {
    @Override
    public void apply(RequestTemplate template) {
        ServletRequestAttributes attributes = (ServletRequestAttributes) 
            RequestContextHolder.getRequestAttributes();
        HttpServletRequest request = attributes.getRequest();
        
        // 获取网关透传的用户信息
        template.header("user-id", request.getHeader("user-id"));
        template.header("username", request.getHeader("username"));
    }
}

// 3. 下游服务拦截器还原到SecurityContextHolder
@Component
public class HeaderInterceptor implements HandlerInterceptor {
    @Override
    public boolean preHandle(HttpServletRequest request, 
                            HttpServletResponse response, 
                            Object handler) {
        String userId = request.getHeader("user-id");
        String username = request.getHeader("username");
        
        // 放入SecurityContext
        LoginUser loginUser = new LoginUser();
        loginUser.setUserId(Long.parseLong(userId));
        loginUser.setUsername(username);
        SecurityUtils.setLoginUser(loginUser);
        
        return true;
    }
}
```

### 3. 延时双删策略解决主从延迟

**问题**：MySQL主从架构下，写入主库后立即读从库，可能读到旧数据。

**解决方案**：延时双删策略。

```java
public void updateProduct(Product product) {
    // 1. 更新前先删除缓存
    redisService.deleteObject("product:sku:" + product.getId());
    
    // 2. 更新数据库
    productMapper.updateById(product);
    
    // 3. 延时500ms后再次删除缓存
    CompletableFuture.runAsync(() -> {
        try {
            Thread.sleep(500);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        redisService.deleteObject("product:sku:" + product.getId());
    });
}
```
