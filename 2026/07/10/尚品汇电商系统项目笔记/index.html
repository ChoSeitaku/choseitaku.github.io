尚品汇电商系统 - 微服务架构实践

一个基于 Spring Cloud Alibaba 的分布式微服务电商平台，支持 PC 后台管理 + H5 移动端双端访问。

项目简介

尚品汇是一套完整的 B2C 电商系统，采用前后端分离架构，基于若依框架二次开发。项目涵盖商品管理、购物车、订单、支付、用户管理等电商核心业务，实现了从商品浏览到下单支付的完整购物流程。

技术栈：Spring Boot 3.0 + Spring Cloud Alibaba + MyBatis-Plus + Redis + RabbitMQ + MinIO
项目规模：10+ 微服务模块，50+ 数据库表
项目地址：https://github.com/ChoSeitaku/shangpinhui-ecommerce

后台管理界面

核心功能模块

1. 用户模块 (spzx-user)

功能概述：管理 H5 移动端用户信息，包括用户注册、登录、收货地址管理等。

核心表结构：

  • user_info - 用户基本信息表
  • user_address - 用户收货地址表
  • region - 地区数据表

技术实现：

  • 支持手机号 + 验证码 + 密码的注册方式
  • 收货地址支持省市区三级联动
  • 用户密码采用 BCrypt 加密存储

2. 商品模块 (spzx-product) - 核心模块

功能概述：商品的全生命周期管理，包括商品发布、上下架、库存管理等。

核心表结构：

技术亮点：

1. Redis位图实现商品上下架快速判断

设计思路：使用 Redis Bitmap 存储商品上下架状态，相比传统方案（查询数据库或普通缓存），具有以下优势：

  • 内存效率极高：每个商品只占用1个bit位
  • 查询时间复杂度 O(1)：直接位运算
  • 支持批量操作：可一次性查询多个商品状态

2. 分布式锁 + Lua脚本的缓存查询

设计思路：

  • 防缓存击穿：分布式锁确保只有一个线程查询数据库
  • 防缓存穿透：空值也缓存，设置较短过期时间
  • 原子释放锁：Lua脚本保证比较+删除的原子性
  • 自旋重试：获锁失败时等待后重试，提高成功率

3. 数据库乐观锁实现库存扣减

设计思路：

  • 通过 WHERE available_num >= #{skuNum} 条件保证不会超卖
  • 数据库层面的原子操作，无需引入Redis预扣减
  • 返回影响行数为0时，表示库存不足

6. 渠道模块 (spzx-channel) - BFF聚合层

功能概述：H5前台的 BFF（Backend For Frontend）聚合层，不直接操作数据库，而是远程调用各微服务聚合数据。

商品详情页聚合示例：

设计思路：

  • 前端只需调用 channel 层的接口，无需关心后端微服务划分
  • 一次请求聚合多个远程调用，减少前端请求次数
  • 前后端解耦，后端服务拆分不影响前端

技术亮点

1. 延迟消息实现订单超时自动取消

问题：用户下单后30分钟内未支付，需要自动取消订单并解锁库存。

解决方案：使用 RabbitMQ 延迟消息插件。

2. Feign调用安全传递用户信息

问题：微服务间 Feign 调用时，如何传递当前登录用户信息？

解决方案：网关解析JWT后写入请求头，Feign拦截器自动携带。

3. 延时双删策略解决主从延迟

问题：MySQL主从架构下，写入主库后立即读从库，可能读到旧数据。

解决方案：延时双删策略。

性能指标

  • 接口响应时间：平均 < 200ms
  • 并发支持：500+ QPS
  • 缓存命中率：95%+
  • 系统可用性：99.9%

个人职责

  1. 负责商品模块开发：设计商品表结构，实现商品CRUD、SKU管理、库存管理等功能
  2. 负责购物车模块开发：基于Redis实现购物车的增删改查
  3. 负责订单模块开发：实现订单创建、取消、防重复提交、超时自动取消等功能
  4. 负责支付模块对接：对接支付宝支付，处理支付回调
  5. 负责渠道模块开发：实现H5前台BFF聚合层，聚合多个微服务数据
  6. 参与架构设计：参与微服务架构设计，制定技术方案

项目总结

通过本项目，我深入掌握了：

  1. 微服务架构设计：服务拆分、注册发现、配置中心、熔断降级
  2. 分布式系统问题：分布式锁、分布式事务、数据一致性
  3. 高并发场景处理：缓存设计、消息队列、乐观锁
  4. 电商业务流程：商品管理、购物车、订单、支付的完整链路
  5. 性能优化经验：Redis位图、分布式锁缓存、数据库优化

这个项目让我从理论到实践，全面提升了微服务架构的设计与开发能力。
